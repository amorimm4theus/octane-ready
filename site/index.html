The problem in 30 seconds

The bug PHP-FPM hides and Octane shows

Octane makes Laravel fast by booting the app once per worker instead of once per request. The catch is memory: anything you keep in a static property stays there for the next request.

PHP-FPM: every request starts from zero

The process forgets everything after each request, so static state is harmless.

  • Request 1 · tenant acme → static = acme
  • memory cleared
  • Request 2 · no tenant → static = public ✓

Octane: one worker, thousands of requests

The worker stays alive. The static from request 1 is still there in request 2.

  • Request 1 · tenant acme → static = acme
  • same worker, same memory
  • Request 2 · no tenant → static = acme ✗
// Legacy code: worked for years on PHP-FPM
class TenantContext
{
    private static ?string $tenant = null;

    public static function set(string $t): void
    {
        self::$tenant = $t;
    }
}
$ ./leak-check.sh   # naive port, real Swoole server
FAIL tenant: request without header got 'acme'
FAIL memory: static cache grew to 2001 entries

$ ./leak-check.sh   # after the fix
PASS tenant: request without header got 'public'
PASS memory: static cache has 0 entries

claude plugin marketplace add amorimm4theus/octane-ready
claude plugin install octane-ready@octane-ready

Tutorial

Your first audit, step by step

Example with Claude Code. In other agents the steps are the same, only the way you call the skill changes.

Open your project

Go to the root of a Laravel app that uses Octane, or that you plan to move to Octane.

cd ~/projects/my-laravel-api
claude

Run the audit

Without --fix it only reads your code. It takes a few minutes on a large app.

/octane-ready:octane-audit

Read the report

Critical findings first. Each one says where it is, why it leaks and how to fix it. You also get a "checked and safe" list, so you know the audit was complete, not just a grep.

Example report (file names shortened):

Fix with a test first

Ask for the fix. For each critical finding it writes a Pest test that simulates two requests on the same worker, shows it failing, then fixes the code and shows it passing.

/octane-ready:octane-audit --fix

Add the safety net

Restart workers from time to time, so a leak you missed cannot grow forever. It is a safety net, not the fix.

php artisan octane:start --workers=8 --max-requests=1000

What it catches

Patterns that look safe and are not

Request data in statics

User, tenant, locale or actor in a static property. The next request inherits it.

Memos keyed by object id

spl_object_id($request) looks scoped, but PHP reuses ids once an object is freed.

Reset on some paths only

Cleared in a middleware for writes, read on GET routes that never clear it.

Singletons holding the Request

Resolved at boot or in octane.warm, they keep the first request forever.

Per-worker caches

forget() clears one worker. The others keep serving stale data.

Caches that never shrink

Static arrays keyed by URL, user or query grow until the worker dies.

FAQ

Questions

Does it change my code?

No. The audit is read-only. It only changes code when you run it with --fix or approve a fix, and then it writes a failing test first.

Do I need Swoole installed to use it?

No. The audit reads code. The tests it writes simulate worker reuse inside your normal test suite, so they run in CI without Swoole.

Does it work with Laravel Boost?

Yes. Boost covers general Laravel guidelines. This kit focuses on migration and long-lived workers.

Does it cover queue workers?

Yes. queue:work and Horizon are long-lived processes too, so the same rules apply to code that runs in jobs.

How do I remove it?

Claude Code: claude plugin uninstall octane-ready@octane-ready. Other agents: delete the three skill folders.
