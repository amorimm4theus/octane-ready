O problema em 30 segundos

O bug que o PHP-FPM esconde e o Octane mostra

O Octane deixa o Laravel rápido porque sobe o app uma vez por worker, e não uma vez por requisição. O detalhe é a memória: o que você guarda numa propriedade static continua lá na próxima requisição.

PHP-FPM: cada requisição começa do zero

O processo esquece tudo depois de cada requisição, então estado static não faz mal.

  • Requisição 1 · tenant acme → static = acme
  • memória limpa
  • Requisição 2 · sem tenant → static = public ✓

Octane: um worker, milhares de requisições

O worker continua vivo. O static da requisição 1 ainda está lá na requisição 2.

  • Requisição 1 · tenant acme → static = acme
  • mesmo worker, mesma memória
  • Requisição 2 · sem tenant → static = acme ✗
// Código legado: funcionou por anos no PHP-FPM
class TenantContext
{
    private static ?string $tenant = null;

    public static function set(string $t): void
    {
        self::$tenant = $t;
    }
}
$ ./leak-check.sh   # port ingênuo, servidor Swoole real
FAIL tenant: request without header got 'acme'
FAIL memory: static cache grew to 2001 entries

$ ./leak-check.sh   # depois da correção
PASS tenant: request without header got 'public'
PASS memory: static cache has 0 entries

Instalar

Escolha o seu agente

Leva um minuto. Nada muda no seu código até você pedir uma correção.

Kit completo: skills, agentes e hooks. Rode no terminal:

claude plugin marketplace add amorimm4theus/octane-ready
claude plugin install octane-ready@octane-ready

Depois abra o Claude Code no seu projeto e digite /octane-ready:octane-audit.

Instala as três skills nos agentes que você escolher, usando a CLI comunitária skills. Precisa de Node.js.

npx skills add amorimm4theus/octane-ready

Depois peça ao seu agente: Use a skill octane-audit neste projeto.

Cada skill é uma pasta autocontida. Copie para a pasta de skills do seu agente, por exemplo .claude/skills/ ou .agents/skills/ (confira na documentação do seu agente).

git clone --depth 1 https://github.com/amorimm4theus/octane-ready /tmp/octane-ready
mkdir -p .agents/skills
cp -r /tmp/octane-ready/skills/* .agents/skills/

Cole o prompt do topo desta página em qualquer agente de código que consiga ler uma URL. Ele segue o mesmo checklist da skill, só lendo o código.

Tutorial

Sua primeira auditoria, passo a passo

Exemplo com o Claude Code. Em outros agentes os passos são os mesmos, só muda o jeito de chamar a skill.

Abra o projeto

Vá para a raiz de um app Laravel que usa o Octane, ou que você pretende levar para o Octane.

cd ~/projetos/minha-api-laravel
claude

Rode a auditoria

Sem --fix ela só lê o código. Leva alguns minutos num app grande.

/octane-ready:octane-audit

Leia o relatório

Os críticos vêm primeiro. Cada achado diz onde está, por que vaza e como corrigir. Você também recebe a lista "conferido e seguro", para saber que a auditoria foi completa e não só um grep.

Corrija com teste primeiro

Peça a correção. Para cada achado crítico ele escreve um teste Pest que simula duas requisições no mesmo worker, mostra o teste falhando, corrige o código e mostra o teste passando.

/octane-ready:octane-audit --fix

Coloque a rede de segurança

Reinicie os workers de tempos em tempos, para que um vazamento que passou não cresça para sempre. É rede de segurança, não é a correção.

php artisan octane:start --workers=8 --max-requests=1000

O que ele pega

Padrões que parecem seguros e não são

Dado da requisição em static

Usuário, tenant, idioma ou operador numa propriedade static. A próxima requisição herda.

Memo indexado por id de objeto

spl_object_id($request) parece isolado por requisição, mas o PHP reaproveita ids quando o objeto é liberado.

Limpeza só em alguns caminhos

Limpo num middleware de escrita, lido em rotas GET que nunca limpam.

Singletons que guardam o Request

Resolvidos no boot ou no octane.warm, ficam com a primeira requisição para sempre.

Cache por worker

O forget() limpa um worker só. Os outros continuam servindo dado velho.

Caches que nunca diminuem

Arrays static indexados por URL, usuário ou busca crescem até o worker morrer.

Perguntas frequentes

Dúvidas

Ele altera o meu código?

Não. A auditoria só lê. Ela só altera código quando você roda com --fix ou aprova uma correção, e aí escreve primeiro um teste que falha.

Preciso do Swoole instalado?

Não. A auditoria lê o código. Os testes que ela escreve simulam o reuso do worker dentro da sua suíte normal, então rodam no CI sem Swoole.

Funciona junto com o Laravel Boost?

Sim. O Boost cobre as diretrizes gerais do Laravel. Este kit foca em migração e workers de longa duração.

Vale para queue workers?

Sim. queue:work e o Horizon também são processos de longa duração, então as mesmas regras valem para código que roda em jobs.

Como removo?

Claude Code: claude plugin uninstall octane-ready@octane-ready. Outros agentes: apague as três pastas de skill.
